# اسکیلورا (Skillora) | آکادمی آنلاین

اسکیلورا یک صفحه‌ی فرود (Landing Page) فارسی و راست‌چین برای یک آکادمی آموزش آنلاین است. این پروژه را برای تمرین **Tailwind CSS** و مقایسه‌ی **jQuery با JavaScript خام** ساخته‌ام.

🔗 **مشاهده‌ی خروجی پروژه:** [https://ghazal-hassanabadi.github.io/Tabs-Accordion-jQuery/](https://ghazal-hassanabadi.github.io/Tabs-Accordion-jQuery/)

---

## سایت چیست و چه کاری می‌کند؟

صفحه‌ی معرفی یک آکادمی آنلاین است که کاربر در آن می‌تواند دوره‌ها را بر اساس دسته‌بندی ببیند، سرفصل‌ها را باز و بسته کند و پاسخ سوالات متداول را بخواند. بخش‌های سایت:

- **هدر ثابت (Fixed Header):** لوگو، منوی اصلی، کادر جستجو و دکمه‌ی حساب کاربری. در موبایل منوی همبرگری دارد.
- **هیرو (Hero):** شعار اصلی، دکمه‌ی مشاهده‌ی دوره‌ها و لینک معرفی پلتفرم.
- **دسته‌بندی دوره‌ها (Tabs):** شش تب برای عکاسی و تدوین، طراحی و گرافیک، زبان‌های خارجی، بازاریابی دیجیتال، هوش مصنوعی و کسب‌وکار. هر تب توضیح و تصویر مخصوص خودش را دارد.
- **سرفصل‌های هر دوره (Accordion):** در هر تب، سه سرفصل وجود دارد که با کلیک باز و بسته می‌شود و فلش کنارش می‌چرخد.
- **چرا اسکیلورا؟:** سه کارت مزیت (مدرک معتبر، پشتیبانی حرفه‌ای، اساتید متخصص) و یک بنر.
- **سوالات متداول (FAQ):** آکاردئونی که هر بار فقط یک پاسخ را باز نگه می‌دارد.
- **فوتر:** لینک‌های سریع، دسته‌بندی‌ها و شبکه‌های اجتماعی.
- **دکمه‌ی بازگشت به بالا.**

سایت **موبایل‌فرست** و کاملاً **ریسپانسیو** است و برای زبان فارسی با `dir="rtl"` و فونت Vazirmatn طراحی شده است.

## تکنولوژی‌ها

- HTML5 (ساختار معنایی و RTL)
- **Tailwind CSS v4** با CLI (رنگ‌ها و فونت سفارشی در `@theme`)
- jQuery 
- **JavaScript خام (Vanilla)** (نسخه‌ی دوم جاوااسکریپت)
- Font Awesome (آیکون شبکه‌های اجتماعی) و فونت Vazirmatn

### تنظیمات Tailwind

رنگ‌های برند و فونت فارسی در فایل ورودی تیلویند تعریف شده‌اند و در کل پروژه با کلاس‌هایی مثل `bg-brand-ink` و `text-brand-sand` استفاده می‌شوند. در پروژه هیچ CSS سفارشی جدا ننوشته‌ام و همه‌ی استایل‌ها با کلاس‌های Tailwind نوشته شده‌اند.

| brand-ink | `#202630` |
| brand-cream | `#F4EFE9` |
| brand-sand | `#D5C2AE` |
| brand-mist | `#A8A29A` |

## تمرین jQuery و JavaScript خام

این پروژه تمرین ۲ فاز jQuery است: **Accordion و Tabs را یک بار با jQuery و یک بار با JavaScript خام بساز و حجم و خوانایی را مقایسه کن.**

### روش کار

HTML و استایل‌ها در هر دو نسخه یکی است و فقط منطق جاوااسکریپت را دو بار نوشتم. هر نسخه را در **فایل جداگانه** گذاشتم (`index.jquery.js` و `index.vanilla.js`) و برای اندازه‌گیری، در `index.html` یکی را فعال و دیگری را **کامنت** کردم. هر دو را هم‌زمان فعال نکردم، چون هر رویداد دو بار اجرا می‌شد و آکاردئون خراب می‌شد.

هر دو نسخه این کارها را انجام می‌دهند:

- تب‌های دسته‌بندی دوره‌ها
- آکاردئون سرفصل‌های هر دوره
- آکاردئون سوالات متداول
- منوی موبایل (باز و بسته شدن و تغییر آیکون)

### نحوه‌ی ساخت

هر دو نسخه را با کمک هوش مصنوعی (AI) و **بخش‌به‌بخش** پیش بردم: کد را تیکه‌تیکه تحلیل کردم، معادل هر خط jQuery را در JavaScript خام پیدا کردم و بعد خودم آن را نوشتم و تست کردم.

### نتیجه‌ی اندازه‌گیری

حجم دانلودی با تب Network مرورگر (فیلتر JS) گرفته شده است.

| مورد | jQuery | Vanilla |
|---|---|---|
| فایل خودم (روی دیسک) | 1,804 بایت | 3,035 بایت |
| فایل خودم (Network) | 2.1 kB | 3.3 kB |
| کتابخانه‌ی jQuery (Network، gzip) | 30.7 kB | ندارد |
| **جمع دانلودی کل JS** | **32.8 kB** | **3.3 kB** |
| تعداد خط | 63 | 105 |

### خوانایی

نسخه‌ی jQuery کوتاه‌تر است، چون حلقه روی عنصرها را خودش انجام می‌دهد (iteration ضمنی) و متدهایی مثل `addClass` و `toggleClass` یک‌خطی‌اند. در Vanilla باید با `forEach` حلقه بزنم و از `classList` استفاده کنم، پس کد طولانی‌تر ولی صریح‌تر است و دقیقاً مشخص است چه اتفاقی می‌افتد.

### تفاوت‌های رفتاری که دیدم

- jQuery اگر عنصری را پیدا نکند بی‌صدا هیچ کاری نمی‌کند. در Vanilla، `querySelector` مقدار `null` می‌دهد و خطا می‌آید.
- در تابع معمولی، `this` همان عنصر کلیک‌شده است. داخل `forEach` این‌طور نیست و باید قبل از حلقه آن را در متغیر نگه دارم.
- `querySelectorAll` فقط یک لیست می‌دهد و خودکار روی همه‌ی عنصرها اعمال نمی‌شود.

### نتیجه‌گیری

کد خودم در Vanilla حدود ۶۷٪ بلندتر است، ولی کل چیزی که مرورگر دانلود می‌کند حدود **۱۰ برابر کمتر** است (۳٫۳ در برابر ۳۲٫۸ کیلوبایت)، چون کتابخانه‌ای لازم نیست. برای پروژه‌ی جدیدی مثل اسکیلورا، Vanilla را انتخاب می‌کنم. jQuery فقط برای نگهداری پروژه‌های قدیمی یا قالب‌های وابسته به آن منطقی است.

## مشکلات پیش‌آمده و راه‌حل

### قاطی شدن پروژه‌ها در گیت‌هاب

در طول تمرین‌ها، پروژه‌های مختلفم در یک ریپازیتوری قاطی شده بودند. با کمک هوش مصنوعی و ابزار **Git**، پروژه‌ها را از هم **جدا و مستقل** کردم، طوری که **تاریخچه‌ی کامیت‌ها از بین نرفت**. اکنون این پروژه ریپازیتوری مخصوص خودش را دارد و روی GitHub Pages منتشر شده است.

### خروجی اضافه در Tailwind

در ابتدا فایل CSS خروجی پر از کلاس‌های بی‌استفاده بود، چون Tailwind v4 به‌صورت خودکار کل پروژه را اسکن می‌کند. با خاموش کردن اسکن خودکار (`source(none)`) و معرفی دستی پوشه‌های `html` و `js`، خروجی تمیز شد.

### مشکلات ریسپانسیو

- تب‌ها در دسکتاپ کوتاه‌تر از کارت بودند. با هم‌عرض کردن تب‌ها (`md:flex-1`) و حذف گردی بالای کارت حل شد.
- ردیف دسته‌بندی و لینک‌های سریع فوتر در موبایل: با گرید دوستونه و `justify-center` کنار هم و وسط قرار گرفتند.
- نبود منو در موبایل: دکمه‌ی همبرگری و پنل منوی موبایل اضافه شد.
